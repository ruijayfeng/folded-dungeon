## 人话版

### 一句话
先修旋转几何与数据模型这两个地基问题，再按 M0→M5 一层层做出可玩版本。

### 为什么
不先修地基就直接写代码，房间旋转和数据结构一定返工；没有任务顺序，就会做到哪算哪、无法验收。

### 步骤白话
- **先做 Phase 0：** 把 9×7 旋转对不齐、数据模型混入场景、放置校验缺分支这几件事在文档和规格上定死；做完能看到一份不再返工的规则清单。
- **再做 M0：** 建 Godot 工程、房间图与门校验、无头测试；做完能在命令行构造出一个合法 5×5 布局。
- **然后 M1：** 让角色能在房间里走、穿门、在构筑节点放房间；做完能亲手摆一个房间并走进去。
- **接着 M2：** 让热量、毒雾、能量真的在房间之间流动并触发爆燃等反应；做完能看到熔炉→毒雾→镜面的连锁。
- **再 M3：** 加入敌人、投射物、击退、状态；做完能打完整场战斗，换布局结果不同。
- **然后 M4：** 串成一层完整流程（奖励、商店、Boss、结算）；做完能连续玩 15–20 分钟。
- **最后 M5：** 补齐 12 房间、折叠、平衡、美术与导出；做完拿到可发布的版本。

### 怎样算完成
- M0 完成：无头测试全绿，脚本能构造布局，门位对齐校验通过。
- M2 完成：文档示例的爆燃链路在测试里逐回合复现。
- M4 完成：能连续游玩一层并通关/失败结算。
- M5 完成：12 房间、折叠、存档、Windows 构建与验收清单全部通过。

### 易踩坑
- **9×7 不是正方形**：旋转 90° 后门位必然错位，先按 Phase 0 的几何方案定死再写代码。
- **决策未确认不等于不能做**：本计划按 `Assumptions` 的建议值推进；若你否决某条，只改对应任务，不要边做边改。
- **Godot 的 `.tscn`/`.tres` 不要手改**：UID/导入缓存易坏，用 `godot` 技能的脚本或编辑器操作。

## 执行方式与并行建议

- **执行顺序：** Phase 0 → M0 → M1 → M2 → M3 → M4 → M5。阶段出口不通过不进入下一阶段。
- **可并行（文件不重叠时）：**
  - M0 内：M0-2（core/fixed、rng）与 M0-3（data/、grid 数据类）与 M0-6（tests/）可并行；
  - M1 内：M1-1（presentation/rooms）与 M1-2（core/combat、grid）可并行；
  - M2 内：M2-1/M2-2（core/rules、tests）与 M2-5（data/rooms）可并行；M2-7（presentation）在 M2-4 后；
  - M3 内：M3-3（projectile）与 M3-4（status/hazard）可并行；M3-5（AI）需等待 M3-4；
  - M4 内：M4-1/M4-2（core/run）与 M4-3 的 UI 部分可并行；M4-4 Boss 需 M3 完成。
- **并行写作用域分离（若使用 Agent Teams）：** 模拟层写 `game/core/`、表现层写 `game/presentation/`、内容数据写 `game/data/`、测试写 `game/tests/`；同一任务不允许两人改同一文件。
- **每完成一个 Task：** 勾选本计划对应条目 → 提交 commit（格式 `TaskID: 简述`）→ 若改动设计/接口，同步 `docs/`。

## Definition of Done（每个 Task 通用）

- 代码为带类型的 GDScript，无 SCRIPT ERROR / 解析错误；
- 相关单元/场景测试在无头模式通过，失败退出码非 0；
- 涉及规则的改动有确定性/黄金回放测试；
- 设计或接口有变化时更新对应 `docs/` 与决策记录；
- 不留未跟踪的调试代码与 `print` 噪音；
- 没有引入 GPL/AGPL/无许可证代码到 `game/`（借鉴 MIT/Apache 需在文件头标注来源）。
