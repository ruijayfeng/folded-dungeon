# 03 · 美术方向与资产复用调研（D11 前置）

> 调研时间：2026-10-31。**目的：回答"做像素是不是最好的选择、Godot 生态里有没有现成资产/开源项目可用"**，为 D11 美术方向定稿提供依据。
> 说明：许可证信息均为本次直接访问官方页面/仓库许可证核实；**未下载整包做实际集成验证**，落地前会再复核一次许可证文本。

## 0. 先回答两个问题

**Q1：像素是什么时候确认的？**

**从未确认。** `docs/02` 里 D11 一直是"待确认"，`docs/07` 也只列了 A/B/C 三个候选方向；2026-10-31 我先出了三张同场景概念图（见 [`docs/art-concepts/`](../docs/art-concepts/)），并在消息里推荐 A（像素），但这只是**建议**，不是既成决策。游戏代码中的表现层目前仍是占位色块，没有做任何正式美术改造。

**Q2：像素真的是最好的选择吗？**

不是"最好看"，而是**目前最省事、最不容易踩版权坑**的路线。原因不是审美，而是供给侧：

- 免费、许可干净、可直接商用的 2D 俯视地牢素材，**几乎全是像素**（Kenney / 0x72 / OpenGameArt / DCSS 都是）；
- 非像素（矢量/手绘/平涂）的俯视地牢素材**基本没有免费完整包**，多是付费商店素材，或需要自己画；
- Godot 的"开源项目"能复用的大多是**代码/架构/管线**，完整可复用的游戏美术很少，且仓库的 MIT 通常只覆盖代码，不覆盖素材。

所以真正的分叉是：

- **接受像素** → 用 CC0 像素包拼装，工作量最低、风险最低（路线 A）；
- **不接受像素** → 现成免费素材这条路基本走不通，需要**自研矢量/墨线资产**（路线 B，概念图 B/C 的路线），工作量大但风格独一无二；
- 3D 低多边形是第三条路（路线 C），有 CC0 素材，但要重写表现层，工作量大。

### 供给侧结论

- **像素**：CC0 主包（Kenney 130 个 / 0x72 406KB）+ CC0 内容库（DCSS）+ OFL 中文字体，**可以做到全程 0 付费、0 署名义务**（CC-BY 的 Dawnlike 可选）。
- **非像素**：没有找到同等规模的免费俯视地牢包；商店里的非像素模块化地牢 tileset 多为付费（如 [2D Modular Core Dungeon Tileset](https://gamedevmarket.net/asset/2d-modular-core-dungeon-tileset-top-down)），且风格未必匹配。
- **3D 低多边形**：Kenney [Mini Dungeon](https://kenney.nl/assets/mini-dungeon) 为 3D·CC0（30 文件，含动画/角色 rig），视觉上限高，但要改表现层。

## 2. 开源 Godot 项目里能复用什么

| 项目 | 许可 | 能复用什么 | 美术资产可用性 | 结论 |
|---|---|---|---|---|
| [statico/godot-roguelike-example](https://github.com/statico/godot-roguelike-example) | MIT（代码） | Godot 4 roguelike 结构、**Dawnlike 图块导入管线**（`art/gen_*.py` + `.gd`，把 tileset 切成命名图块） | Dawnlike = CC-BY 4.0，作者**故意不整包入库**，要求使用者自行阅读许可 | **最适合借鉴"素材如何进 Godot"**，不要直接搬图 |
| [ramaureirac/godot-tactical-rpg](https://github.com/ramaureirac/godot-tactical-rpg) | MIT（代码） | 战棋回合/寻路/单位交互结构 | `assets/textures` 为作者自带素材，README **未标注素材许可** | **只参考代码**；素材复用需单独确认，属于典型"仓库 MIT ≠ 素材可用"的例子 |
| [Bozar/godot-4-roguelike-tutorial](https://github.com/Bozar/godot-4-roguelike-tutorial) | MIT（代码） | Godot 4 回合制 roguelike 教学结构 | 仓库基本不含完整美术（只有字体等零散 png） | 参考代码，不指望美术 |
| [theshaggydev/unto-deepest-depths-prototype](https://github.com/theshaggydev/unto-deepest-depths-prototype) | MIT（代码） | 战斗循环/单位组件结构 | **仓库不含美术资产**（只有 `src/`） | 参考代码 |
| [godotengine/godot-demo-projects](https://github.com/godotengine/godot-demo-projects) | MIT | 引擎特性示例 | `2d/` 下有 RPG 示例但没有"地牢/战棋"完整素材 | 不适用 |

**结论：** "Godot 有很多开源项目"是真的，但**开源项目给的是代码与管线，不是能直接用的游戏美术**；美术供给侧基本集中在 CC0/CC-BY 素材站点。

## 3. 三条可行路线对比

| 维度 | A · CC0 像素包拼装 | B · 自研矢量/墨线资产 | C · 3D 低多边形 |
|---|---|---|---|
| 视觉来源 | Kenney Tiny Dungeon（主）+ 可选 0x72/DCSS 补件 + Fusion Pixel 字体 | 我们自己用 SVG/程序化生成（概念图 B/C 路线） | Kenney Mini Dungeon 3D（CC0） |
| 许可风险 | **极低**（CC0；字体 OFL 需随包附许可） | 极低（全自研） | 低（CC0） |
| 工作量 | **中**（拼 TileSet、角色动画、粒子、UI 换皮） | **中高**（要画/生成整套 tiles、角色、UI、特效） | **高**（表现层 3D 重写：相机、光照、拾取、动画） |
| 视觉上限 | 经典 roguelike；容易被说"复古" | 独特、与"规则装置"气质合；质量取决于我们的美术能力 | 光影/材质最"像现代游戏" |
| 与现有 9×9/5×5 结构契合度 | 高（16×16 整数倍缩放到 64px，门/墙可拼） | 高（几何完全按我们的规则画） | 中（3D 网格与 2D UI 需桥接） |
| 后续换正式美术 | 容易（同规格替换图块） | 中等（替换整套 SVG/纹理） | 中等（替换模型） |
| 适合"先看到游戏感" | ✅ 最直接 | ✅ 但需要更长制作 | ✅ 但基建多 |

## 4. 建议

1. **如果接受像素风格**：走 **路线 A**。主包用 **Kenney Tiny Dungeon（CC0, 16×16, 130 文件）**，中文 UI 用 **Fusion Pixel Font（OFL）**；缺的门/机关/特效按现有 `Palette` 自绘补件（自绘部分版权归本项目）。这是"最快让游戏像游戏、且许可最干净"的方案。
2. **如果明确不想要像素**：走 **路线 B**，以概念图 B（战术极简）或 C（手绘剪影）为基准做**自研矢量资产**。不要指望找到免费非像素地牢包；我们已有 SVG 工具链（README hero/机制图就是自研 SVG），可以画一套统一的 tiles/角色/UI，再导入 Godot 当纹理用。
3. **路线 C（3D）** 只有在愿意把表现层从 2D 换到 3D 时才考虑；它能显著提升"现代游戏感"，但和当前 9×9 网格、2D HUD 的整合成本最高。

> **无论选哪条路线，模拟层（`game/core/`）和 86 个测试都不动**；美术与手感全部在 `presentation/` 层实现，并通过 `RuleEngine` 事件日志驱动特效。

---

## 5. 待设计者确认

1. 风格方向：**A 像素 / B 自研矢量（极简或墨线）/ C 3D 低多边形**；
2. 若选 A：是否接受"先用 CC0 像素包做正式版"，还是"像素包仅作占位、之后换自研像素"；
3. 是否需要中文像素字体（Fusion Pixel，OFL）打包进游戏；
4. 是否允许 CC-BY 素材（Dawnlike 等，需要署名）——项目当前定位 Apache-2.0，CC0/OFL 最省事。
