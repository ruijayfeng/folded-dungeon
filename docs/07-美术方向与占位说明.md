# 07 · 美术方向与占位说明（M5）

> 状态：D11（美术方向）仍待设计者确认。当前全部游戏内表现使用**占位色块 + Palette**，方便验证可读性与规则反馈；正式美术不在首个可玩版本范围。

## 1. 当前占位方案

- 房间内部：9×9 色块 Tile（地面 `#2b2b3d`、墙 `#111119`、门 `#c9a227`）。
- 通道可视化：整房半透明染色（Heat 红、Toxin 绿、Cold 蓝、Charge 黄、Airflow 淡紫），透明度随通道值。
- 单位：玩家蓝圆、敌人红圆 + 血条。
- 宏观 5×5 地图：空/有房/当前房间/构筑 ghost 四色。
- 统一色板：`game/presentation/theme/palette.gd`（`Palette`）。

## 2. 待确认的美术方向（D11）

| 方向 | 优点 | 风险 |
|---|---|---|
| A. 精细像素风（32×32 或 16×16 tile） | 与 Godot 生态/原型契合、成本可控 | 需统一 tileset 与动画规范 |
| B. 2D 手绘（HD 形状 + 少量帧动画） | 辨识度高、适合复杂规则表现 | 成本高、需美术产能 |
| C. 极简几何 + 粒子（当前占位升级版） | 规则反馈最清晰、实现最快 | 商业辨识度较弱 |

## 3. 占位→正式资源替换顺序（建议）

1. 房间地面/墙/门 tileset（保证 9×9 与四朝向旋转正确）；
2. 玩家/敌人角色 sprite 与朝向；
3. 通道效果（热浪、毒雾、霜冻、电弧/气流）与反应特效（爆燃、反射、充能爆发）；
4. 宏观地图房间图标（类型/状态/连接）；
5. UI/图标统一（蓝图卡、构筑 ghost、商店/事件面板）；
6. 音效与音乐（当前无音频资源）。

## 4. 可读性验收（无论选择哪种方向）

- [ ] 不看文档能区分房间类型与当前通道状态；
- [ ] 旋转后的门位与内部布局一致；
- [ ] 相邻房间的门/传导方向可见；
- [ ] 爆燃/反射/充能等反应有明确的来源与范围反馈；
- [ ] 危险格/危害有预警（下回合是否致命）；
- [ ] 色盲安全：除了颜色，另有图标/纹理区分通道。

## 5. 表现层接入点（供美术实现）

- `RoomView`：地面/墙/门/单位/通道染色；
- `GridMapView`：宏观房间、连接、ghost；
- `RunMode`：HUD/按钮/状态提示；
- 数据源：`RoomLayout`（纯数据）与 `RuleEngine` 事件日志（特效触发）。
