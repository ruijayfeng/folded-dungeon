## A. 待确认决策清单

### D1「折叠」机制的定义（最高优先级）

- **背景：** 标题为《折叠地牢》，但原文只定义了放置/旋转/替换，没有定义「折叠」。若不做，名实不符。
- **选项：**
  - A. 隐喻：不新增机制（成本最低，风险最高）；
  - B. 操作层：旋转/重排即「折叠」（有新意但有限）；
  - C. 机制层：真正的空间折叠（招牌机制，复杂度最高）。
- **建议：** C 的轻量版，首个可玩版本实现两种折叠：
  1. **空间折叠（构筑）**：通过「折叠房」获得每层 1 次折叠权，把两个**都有未连接门**的房间用虚拟边临时连成相邻（效果：可通行 + 可传导），持续到下次构筑；可解除。
  2. **房间折叠（操作）**：休整房/事件中可旋转已放置房间——本质是「折叠自己的地牢」，作为 C 的叙事落地。
- **影响：** 模拟层邻接图必须支持**虚拟边**（不只是 5×5 物理相邻），并纳入连通性/传导/寻路；UI 需表现非物理相邻的连接。
- **状态：** `待确认`

### D2 战斗粒度：单角色战术 vs 小队战术

- **背景：** 原文称「回合制战术」，但未说明控制单位数量。
- **选项：** A. 单角色（范围/位移型战术，像轻度 Into the Breach）；B. 2–3 人小队（更像战棋，UI 与 AI 成本高）；C. 单角色 + 可召唤物/陷阱。
- **建议：** A + C 的简化（首版单角色；房间规则充当「战术工具」）。理由：空间规则已经足够提供战术深度，再加小队会让原型复杂度翻倍。
- **影响：** 回合结构、AI、UI、数值全部不同；**请在 M0 前确认**。
- **状态：** `待确认`（建议 A）

### D3 时间模型：探索是否回合制

- **背景：** 原文「玩家在房间内部进行网格移动」「战斗使用回合制」，未说明探索阶段是否实时。
- **选项：** A. 全程回合制（探索与战斗同一套回合驱动，房间按回合计时）；B. 探索实时、战斗切回合；C. 探索格子移动但非严格回合。
- **建议：** A（全程回合制）。理由：房间效果全部按回合触发，探索若实时，需要另一套时间驱动，且「热浪每两回合」等规则在探索与战斗间会不一致。
- **影响：** 所有房间计时器、事件、存档的基准；影响操作手感（回合制探索会偏慢，需要加速动画/快捷键）。
- **状态：** `待确认`（建议 A）

### D4 房间内部地图的旋转处理（P0-1 已冻结）

- **背景：** 原文要求门随旋转同步旋转，但没说内部地图怎么处理；且原文「9×7」示例不是正方形，旋转后门位必然错位（评审 B1）。
- **结论（2026-10-30 冻结）：** 采用方案 A，并把房间内部网格统一为 **9×9 正方形**。门用「外环墙中点门格 + 墙边中点门锚点」表示；旋转以房间中心为轴，同时作用于门格/门锚点/内部地形/规则方向。4 个朝向 footprint 恒为 9×9，相邻房间门锚点世界坐标严格重合。
- **影响：** 房间内部布局尽量轴对称；美术与表现层按同一朝向渲染；M0-5 用全组合单测守住该不变量。
- **状态：** `已定（P0-1）`

### D5 地牢是「边探索边扩建」还是「先随机生成再改造」

- **背景：** 原文 §3.1 流程（探索 → 获得蓝图 → 构筑 → 继续）与 §4.1 5×5 示例都指向渐进扩建，但「探索的对象是已建房间」还是「初始就有一张随机地图」未明说。
- **建议：** **渐进扩建**：开局只有起始房间 + 1 个相连房间，每清房/事件后进入构筑节点，新房间接入现有地牢；敌人与资源在新房间生成。理由：与「每层 8–12 个已构筑房间」「获得蓝图后放置」的流程一致，也最能体现构筑是玩家的选择。
- **影响：** 决定地图生成器、敌人刷新时机、房间内容生成、Boss 接入方式（Boss 房在玩家构筑到某个深度后解锁放置）。
- **状态：** `待确认`（建议渐进扩建）

### D6 构筑资源与限制模型

- **背景：** 原文强调「建造受资源、位置、房间数量约束」，但没给具体资源。
- **建议（草案）：**
  - **构筑点（BP）**：放置房间花费 1–2 BP；旋转在构筑节点免费；替换返还一半（向下取整）；
  - **金币**：商店购买房间蓝图/强化/消耗品；
  - **房间数上限**：每层与楼层深度相关（首版每层上限 8–12）；
  - **折叠点**：每层 1 次（见 D1）。
- **影响：** 数值与节奏；若资源过松，构筑无取舍；过紧，玩家无法体验组合。
- **状态：** `已定（P0-4 冻结为 M0 可执行值）：BP 放置 1–2、替换返还一半、旋转免费；具体数值待试玩调整`

### D7 敌人是否受房间规则影响 / 是否会用房间规则

- **背景：** 原文只说「敌人和玩家进入毒雾区域会受到影响」，未说明 AI 决策。
- **建议：** 全部受影响（公平性）；AI 分两级实现：L1 基础（攻击、追击、避开致命危害）；L2 进阶（利用自身元素抗性主动站进有利房间、把玩家推进危害）。首个版本做 L1 + 部分 L2。
- **影响：** 需要可配置的敌人属性（各通道抗性/亲和）与伤害来源追踪。
- **状态：** `待确认`（建议全部受影响）

### D8 房间危害是否伤害玩家

- **背景：** 原文只说毒雾影响「敌人和玩家」。
- **建议：** 是，但必须**可预见、可规避、有收益**：玩家站在自己造的危险房间里有成本，同时房间可能提供增益（如蓄能房充能）。这是构筑取舍的重要来源。
- **影响：** 数值、UI 预警、AI 与玩家行为。
- **状态：** `待确认`（建议是）

### D9 可读性方案：玩家如何看懂规则

- **背景：** 原文视觉重点要求「房间联动时具有足够的动画和反馈」，但没规定信息层级。

- **影响：** UI 工作量不小，但这是「策略可信度」的前提，不能延后。
- **状态：** `建议采纳`

## B. AI 补全设计（标注假设）

> 以下内容原始文档缺失或截断，按原文风格补全，供设计者审核。全部为 `【AI 补全 / 待确认】`。

### B1 折叠机制提案【AI 补全 / 待确认】

**三种折叠形态：**

1. **空间折叠（Space Fold）** —— 招牌机制
   - 通过「折叠房」获得每层 1 次折叠权；
   - 选择两个**各有一扇未连接门**的房间，建立一条**虚拟邻接边**：
     - 两房间的未连接门「对折」相连；
     - 允许移动与通道传导通过；
     - 视觉表现为跨地图的虚线折痕 + 折纸动画；
     - 持续到下一次构筑（可解除），解除无消耗。
   - 用途：绕过物理布局限制，把熔炉的热量直接折进毒雾房；把危险房间的火焰折向敌人。
2. **房间折叠（Room Fold）** —— 已在原文 §4.3 体现
   - 休整房/事件中旋转已放置的房间 = 「折叠自己的地牢」；
   - 可定义为消耗一次休息行动点。
3. **规则折叠（Rule Fold）** —— 后续版本
   - 折叠房可以把相邻两个房间的通道状态「合并」结算（例如把毒雾房的毒浓度并入熔炉房判定爆燃），实现更极端的组合。
   - 首个版本**不做**，避免规则复杂度过高。

**实现影响：** 模拟层邻接图 = 物理边 + 虚拟边；连通性校验、传导 BFS、寻路都要支持虚拟边；UI 必须能画出跨地图连接。

### B3 战斗系统提案【AI 补全 / 待确认】

**回合结构（与 D2/D3 绑定，按单角色方案）：**

```text
回合开始
 → 玩家阶段：移动（1 次，移动力 4）+ 行动（1 次：普攻 / 技能 / 互动）
 → 敌人阶段：每个敌人依次「移动（可选）→ 攻击（若在射程）」
 → 环境阶段：见 01 文档 §5.3（状态推进 → 排放 → 毒/火伤害 → 传导 → 反应 → 衰减）
 → 状态检查
```

**基础规则草案：**

| 项 | 草案 |
|---|---|
| 移动 | 4 方向网格（先不做斜向）；每回合 1 次移动，最多 4 格；可穿过门进入相邻房间（跨房间移动消耗剩余移动力） |
| 攻击 | 近战（相邻 1 格）、远程（射线投射物，可被镜面/风暴/重力改写） |
| 位移 | 击退 = 沿攻击方向推 N 格，撞墙/障碍停止并受额外伤害；重力房按重力方向改写击退 |
| 状态 | 燃烧（每回合伤害 + 产 Heat）、中毒（每回合伤害）、寒冷（移动-1）、充能（下次攻击强化）、眩晕（跳过行动） |
| 玩家数值 | HP 10；普攻 2；技能 1–2 个（由起始房间/角色决定） |
| 敌人类型（首版 4 种） | 燃烬（火系，免疫燃烧，受冷克制，死亡自爆 Heat）、毒囊（死亡释放 Toxin）、霜甲（高防、减速攻击、免疫寒冷）、弩手（远程、会换位）；Boss 单独设计 |
| 敌人 AI | L1：能攻击就攻击；否则向玩家移动；避开下一回合会致命的危害格。L2（后续）：利用抗性站进有利房间、把玩家推入危害 |
| 战斗结束 | 全灭敌人 → 奖励（金币/蓝图/构筑点）；玩家死亡 → 本局结束 |

**与空间规则的接口（战斗钩子）：**

| 钩子 | 触发时机 | 用途 |
|---|---|---|
| `on_room_enter(unit, room)` | 进入房间 | 毒雾/热浪/进入效果 |
| `on_turn_start(room)` / `on_turn_end(room)` | 每回合 | 房间计时器、蓄能释放 |
| `on_unit_move(unit, from, to)` | 移动结算 | 重力/减速/陷阱 |
| `on_projectile_path(path)` | 发射时 | 镜面反射、风暴偏转、重力弯折 |
| `on_damage_taken(unit, amount, source)` | 受伤 | 抗性、充能、镜面加成 |
| `on_unit_death(unit, room)` | 死亡 | 自爆、掉落、毒囊破裂 |
| `on_reaction_triggered(recipe, rooms)` | 反应触发 | 视听反馈、日志、镜像联动 |

### B4 单局结构与经济提案【AI 补全 / 待确认】

**一层（Floor）内容：**

| 内容 | 数量（草案） | 说明 |
|---|---|---|
| 起始房间 | 1 | 固定为战斗房或休息房 |
| 普通房间 | 4–6 | 战斗/资源/元素房，清房后给蓝图/金币 |
| 精英房间 | 1 | 高难、必掉蓝图 |
| 事件房间 | 1 | 三选一，可能给临时重排/折叠权 |
| 休整房间 | 1 | 回血、旋转一个房间、替换一个房间 |
| 商店房间 | 1 | 买蓝图/消耗品/强化 |
| Boss 房间 | 1 | 通关本层 |

> 合计 1 + (4–6) + 精英 1 + 事件 1 + 休整 1 + 商店 1 + Boss 1 = 10–12 个房间，与原文「每层 8–12 个已构筑房间」吻合。

**构筑节奏草案：** 每清除 1–2 个房间进入一次构筑节点（获得 BP + 可放置 1 个新房间）；玩家可选择「继续探索已有房间（风险）」或「立即构筑（安全）」。

**经济草案：** 清普通房 +15–25 金币；精英 +50；Boss +100；蓝图可在商店购买（价格 40–80）；构筑点由清房/事件获得。数值全部待试玩。

**Boss 设计方向：** Boss 应「使用」房间规则而非单纯高血量——例如 Boss 会把自己房间的 Heat 推向玩家、会在低血量时引爆相邻毒雾房、会破坏玩家的一个门（封锁传导）。这能直接验证「构筑是战斗解法」这一卖点。
